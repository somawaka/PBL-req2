# GemC 共通生成・表示ルール

## 1. 概念の階層

内部構造は次の階層とする。

`ステークホルダー区分 > 組織類型 > 役割`

- ステークホルダー区分：S1〜S5の固定分類
- 組織類型：対象産業に存在し得る組織の種類
- 役割：その組織内外で技術に関与する具体的な担当

Actor等の別概念へ置換しない。会社名は根拠がある場合だけ使用する。

## 2. 文脈と意味の着眼点

- 文脈はC1〜C6の発散軸である。
- 意味の着眼点は、各文脈から価値変化を考えるための問いである。
- 意味の着眼点を第4軸として掛け合わせない。

## 3. 候補の生成順序

1. 承認済み実行計画から現在の産業と距離を読む。
2. `04_mixed_coverage_rules.md`で使用する主体×文脈の組を確定する。
3. 産業内の具体的な現場、業務、状態を設定する。
4. ステークホルダーを組織類型と役割へ具体化する。
5. 各組み合わせから意味的価値を1件ずつ生成する。
6. 候補ID、件数、主体・文脈の被覆を検査する。

## 4. 候補に含める意味

| 表示項目 | 答える内容 | 書き方 |
|---|---|---|
| 主体×文脈 | 誰の立場から、どの意味の観点で考えたか | `主体名 × 文脈名` |
| 想定する組織・役割 | どのような組織の誰が関係するか | `組織類型／役割` |
| 意味的価値 | 特許がその主体にとって何へ変わるか | 中心的な価値変化を1文で示す |
| 技術とのつながり | 元技術が新しい産業でなぜ機能し得るか | 元技術の能力と新しい対象を接続する |
| 導入前後の変化 | 判断・行動・関係がどう変わるか | `導入前 → 導入後`が分かる1文にする |
| 成立条件・根拠 | 何が満たされれば成立し、根拠は何か | `成立条件：...／根拠：...` |

意味的価値を最重要項目とする。単なる用途名、機能説明、メリットの羅列で終わらせない。

## 5. 人が読む表と機械受け渡しの分離

通常のチャットでは、上記6項目と候補IDだけを日本語表で表示する。

次の情報は通常表示で繰り返さない。

- 産業名と距離：産業概要に表示済み
- 主体IDと文脈ID：候補IDおよび内部データで保持
- 組み合わせパターン番号：固定規則から再計算可能
- 類似なしの記載：情報量が増えるだけなので省略

英語の17列は、ユーザーが`要求機能③用データ`と入力した場合だけ表示する。

## 6. 文章量

- 各セルは原則1文にする。
- 意味的価値は70字程度まで、その他は50字程度までを目安とする。
- 同じ技術説明を複数列へコピーしない。
- 表の前後に候補内容を言い換えた文章を追加しない。
- 30件を出す場合も行数を減らさず、各セルを短くする。

## 7. 候補の保持

- 遠い、不自然、採算不明、実現困難に見えることを理由に削除しない。
- 類似候補を統合しない。類似がある場合だけ相手の候補IDと差を短く残す。
- 市場性、新規性、事業性、技術適合性、実現可能性の評価は要求機能③で行う。
- 不確実性は成立条件と根拠区分へ残す。

## 8. 事実とAI推論の境界

### 固定情報

- ステークホルダーS1〜S5
- 産業A〜S
- 文脈C1〜C6
- 距離ごとの組み合わせ数
- 組み合わせ割当規則
- 候補ID規則
- 人が承認した実行計画

### AIが入力から整理する情報

- 特許記載の機構、課題、効果、現在用途：事実
- 他産業へ移せる能力への抽象化：推論
- 原文からまとめた入力、出力、条件、制約：事実または推論

### AIが発散のために生成する情報

- 19産業の距離と理由
- 産業依存の組織類型と役割
- 意味的価値、技術とのつながり、導入前後の変化
- 成立条件、根拠区分、類似関係

### 禁止する補完

- 入力特許にない構造、性能値、実施条件、実証結果、導入企業、規制適合性を事実として補わない。
- 空欄を別の公報行や一般常識で埋めない。
- 情報がなければ「不明」、発散に必要な仮置きなら「仮定」とする。
- AI生成候補を既に存在する用途、市場、事業として表現しない。
