# 特許CSV入力アダプター

`otb_patents_list.csv`の1行を、発散前確認用の特許理解へ変換する。CSVは1行を1公報として扱う。

## 対象行

1. `公報番号`を一次キーとする。
2. 公報番号指定時は完全一致する1行だけを読む。
3. 未指定時は公報番号と発明の名称だけを表示し、選択を待つ。
4. 類似題名だけで同一発明と判断しない。
5. 複数公報を自動で結合しない。

## CSV列の読み替え

| CSV列 | 特許理解での用途 | 扱い |
|---|---|---|
| 公報番号 | 公報番号 | そのまま「事実」 |
| 発明の名称 | 発明名称 | そのまま「事実」 |
| url | 参照先 | そのまま「事実」 |
| 技術分野 | 現在の用途の手掛かり | 原文は「事実」、用途の要約は「推論」 |
| 背景技術 | 現在の用途・従来状況 | 特許記載として「事実」 |
| 発明が解決しようとする課題 | 仕組みと能力を理解する手掛かり | 特許記載として「事実」 |
| 課題を解決するための手段 | 技術の仕組みの中心 | 特許記載として「事実」。請求項と照合する |
| 発明の効果 | 技術ができることの手掛かり | 特許が主張する効果として「事実」。外部実証済みとはみなさない |
| 発明の概要 | 仕組み・能力・現在用途の補助 | 原文は「事実」、抽象化は「推論」 |
| 発明を実施するための形態 | 使用条件・制約 | 空欄は「不明」 |
| 特許請求の範囲 | 仕組み・必須要素・制約 | 特許記載として「事実」。必須要素を優先する |

## 特許理解の5項目

| 確認項目 | 作成方法 |
|---|---|
| 技術の仕組み（入力→処理→出力） | 入力、主要処理、出力を1文にまとめる |
| 技術ができること | 製品名ではなく、他産業へ移せる動詞句で表す |
| 使用条件・制約 | 明記された必須要素、条件、適用限界をまとめる |
| 現在の用途 | 特許が想定する既存の産業・現場・対象をまとめる |
| 重要な不明点 | 距離判定・候補生成に影響する未記載事項だけを示す |

「入力／出力」を独立項目にせず「技術の仕組み」へ統合する。「条件」と「制約」も統合し、同じ内容を複数項目へ書かない。

## 根拠区分

- 事実：選択行の原文に直接対応する内容
- 推論：原文から導いた要約・抽象化・解釈
- 仮定：発散のために意図的に置く条件
- 不明：選択行だけでは判断できず、仮定も置いていない内容

ユーザー向け表では上記の日本語だけを使う。英語コードを表示しない。

空欄を別の公報行や一般常識で補完しない。対象行確定前に距離分類・候補生成を開始しない。
